# 文档与交付规则

## 源文件与目录

- 所有直接生成的源文件统一放入独立输出目录；若用户未指定，默认目录名为 `project_docs`
- 源文件名默认使用英文语义化命名：`requirements-specification.md`、`high-level-design.md` 等
- 包装层源文件：`delivery-cover.md`、`delivery-index.md`、`delivery-audience-guide.md`

## pandoc 与交付文件

- 只要 pandoc 已安装或命令可执行，就视为可用
- 生成 Markdown 后必须先检测 pandoc；可用则继续转换
- pandoc 不可用时自动安装：
  - Windows：winget → choco
  - macOS：brew
  - Debian/Ubuntu：apt-get
  - RHEL/CentOS/Fedora：dnf → yum
- 交付文件统一使用中文文件名，输出到 `project_docs/交付`
- 默认至少输出英文源 md 和中文 docx；pdf 在打印、归档、签字场景下追加

## 交付目录附加文件

每次生成 交付 目录时，必须额外附带：

- 交付总封面
- 交付清单目录
- 交付文件阅读对象说明

### 交付文件阅读对象说明格式

- 不用 Markdown 表格
- 使用"一个交付文件一个小节"的固定分节格式
- 每个小节字段顺序：主要阅读角色、次要阅读角色、阅读目的、是否必读、建议阅读顺序、备注
- 角色名称优先从以下集合选择：产品经理、业务方、资深用户、软件架构师、后端开发、前端开发、客户端开发、硬件工程师、嵌入式工程师、DBA、测试工程师、运维工程师、SRE、安全工程师、合规人员、制造工程师、供应链人员、售后支持、项目经理、实施顾问、培训人员、终端用户、管理层

## 默认交付物

- 交付总封面
- 交付清单目录
- 交付文件阅读对象说明
- 需求理解与范围说明
- 需求规格说明书
- 总体设计说明书
- 详细设计说明书
- 接口文档 / 通信协议文档
- 数据库设计文档
- 测试计划与测试用例
- 项目实施计划 / 里程碑计划
- 部署与发布说明书
- 运维与售后支持手册
- 制造与生产导入资料
- 合规与认证资料清单
- 用户操作手册
- 架构决策记录

## 按项目类型裁剪

| 项目类型 | 必需交付物 |
|---|---|
| 纯软件 Web/App/中后台 | 需求理解、规格、总体、详细、接口、数据库、测试、部署、运维、ADR |
| 纯后端/平台/中间件 | 需求理解、规格、总体、详细、接口、数据库、测试、部署、运维、ADR |
| 嵌入式/IoT/控制系统 | 需求理解、规格、总体、详细、通信协议、测试、售后支持 |
| 量产硬件 | 设计与测试文档 + 制造/生产导入资料、检验标准、SOP、认证资料 |
| SaaS/平台型 | 需求理解、规格、总体、详细、接口、数据库、测试、部署、运维、里程碑计划、ADR |
| 受监管行业 | 对应类型基础上 + 合规/认证资料、审计留痕要求、风险说明 |
